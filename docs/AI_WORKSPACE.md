# Airplane 助手工作台

从财务或健康进入同一个全页助手。原有饮食、收支、采购和照片候选继续使用。工作台分为对话、待确认操作、Skill 与本轮上下文。

## 账本工具

- 查询范围由用户的日期、食品名或业务目的决定。匹配记录保留完整原值，节省上下文时优先避免无关数据和重复发送。
- 查询库存：按名称返回全部匹配项的名称、数量和单位。晚餐规划另外可取今天的热量、蛋白质和对应目标。
- 查询财务：只返回当天收入、支出合计和笔数。交易明细、备注和历史备份不进入模型请求。
- 查询饮食：按日期和可选食品名返回全部匹配的实际记录，保留原餐次、时间、名称和份量。上一轮查过的日期用于下一轮定位原记录。
- 写入：收支、饮食计划、摄入、运动、采购、库存盘点和补货生成可编辑操作卡。盘点用现有批次分配和库存流水。确认时检查最新版本，再由应用提交。
- 批量变更在本机按顺序校验并预览库存合计。任一候选校验失败时整组不写入。跨财务和健康的批次复用本机待同步记录，用收支 ID 恢复中断的保存。可仅保存，或确认全部后继续本轮。
- 后续：采购一次确认同时入库并关联支出。设计沿用稳定订单 ID、恢复日志和余额校验。再增加按范围查询历史、指定记录更正和操作反馈。

## 后续日常流程

| 用户说法 | 工作台处理 | 账本展示 |
| --- | --- | --- |
| “昨天吃了什么”后接“牛奶那条改成 300g” | 查询指定日，随后在原记录上预览份量、营养和关联库存差异，确认后保存 | 健康历史、趋势和库存流水 |
| “更正昨天的牛奶为 300g，补记午餐 28 元，然后安排晚餐” | 批量核对并保存更正和收支，再核对最新库存与营养摘要 | 原饮食记录、独立午餐支出与待确认晚餐计划 |
| “今天早上 74.5 kg” | 识别称重时间和晨重，确认后保存 | 最新晨重和滚动均值 |
| “这袋鸡胸买了 28 元” | 同一张卡核对实付、分类和入库批次，两个账本统一提交 | 采购记录和财务支出显示关联 |
| “按我常吃的搭一份晚餐” | 读取经选择的库存和今日营养，返回结构化计划。执行后可转为实际摄入 | 计划餐和已确认饮食分别展示 |

只有完成这些常用闭环后，再统一验收真实模型、移动端和完整回归。

## Skill 与上下文

- 内置提示词随代码维护。个人 Skill 是最多 320 字的行为偏好。用户可编辑，也可请助手给出新版，核对并确认后保存。
- 普通消息保留最近四条短消息，总共最多 900 字。旧照片不重发。模型只可请求应用定义的工具。同一轮可逐项查询账本，每项摘要核对后才发送。完整回复可包含多项待确认变更。
- 保存后续办只重发本轮原请求、设备日期、个人 Skill 和已完成的操作类型。继续读取账本时重新获取最新摘要。可以单独重试后续请求。
- 正文通过 Responses API 流式显示。候选卡校验完整响应后才显示。停止或中断会保留输入，局部回复不会写入聊天记录。
- 可在对话列表删除单条本机聊天。已经保存到财务或健康账本的记录仍可从相应页面查看。
- 允许用户新开对话、停止发送摘要、放弃候选或手动填写。对话文本、操作结果、个人 Skill 和 API Key 各自保存在设备。已发送的查询数据也可在本机对话中完整展开，不随旧对话重新发送。选中的照片随本轮结束释放。

## Demo

从 `/assistant/?demo=1` 打开。独立的示例账本用于演示库存盘点、补货、晚餐、收支和 Skill。所有卡片走与正式版相同的预览和确认入口。在同一个标签页切换财务或健康可查看样例账本的变化，不需要 Key 或模型请求。
