# 所有者完全控制 · Airplane 0.9.22

在 AI 设置的本机账本权限里打开「所有者完全控制」。旧版「完整数据权限」已开启的设备会沿用授权。本轮本机访问关闭时，模型收不到本机工具。授权和撤回仍由用户通过设置完成。

## 数据源与能力

| 数据源 | 模型查询 | 按 ID 新增、修改、删除 | 依赖及特殊行为 |
|---|---|---|---|
| 财务交易、收支分类、月预算、余额调整、账本偏好 | 全历史搜索、指定月份或 ID | 记录级工具和原始文档 | 净额按分计算。改已有交易使用原 ID。关联采购的实付另存，采购分摊和历史成本留在采购账。余额、预算沿用原有实时统计。 |
| 饮食和计划 | 全历史，实际与计划均可查 | 记录级工具和原始文档 | 修订原记录，关联库存流水重算。计划和取消项不计实际。外食可无 SKU，未知营养及成本保持空值。 |
| 晨重、运动、每日完整性、健康参数、旧日汇总、TDEE 与历史规则 | 全历史，原始及有效值可查 | 记录级工具和原始文档 | 每日、趋势及周期读取最新账本。旧基线保留原值，只有明确编辑基线时才变化。 |
| SKU、单位、营养、盘点、库存价格、别名、补货清单 | 全历史，按 SKU、ID 和字段 | 记录级工具和原始文档 | 重新计量按当前实盘建立新基准。旧批次、包装和库存流水保留历史单位。停用或归零的 SKU 仍可查询。 |
| 采购订单、批次、分装、库存流水、包装与称重、餐食模板 | 按订单、SKU、原事件或 ID | 记录级工具和原始文档 | 可改单一采购明细。已用明细移出时归档相关历史。盘点、称重、分装、关闭包装优先用业务工具。直接修改多表字段时需保持相关记录一致。 |
| 体检报告、指标、症状、确诊、基础资料和原件引用 | 全历史。可限报告 ID | 记录级工具和原始文档 | 用户自述按来源记录。确诊需医生来源。删报告时移除其指标。删原件时清理报告引用。原件通过专用工具按 ID 发送。 |
| 对话、消息、已归档附件、记忆、Skills 和用户分组 | 跨对话分页，附件可查状态 | 记录级工具和原始文档 | 对话的运行检查点和撤销令牌由程序维护。按需提取旧附件、不随查询发送原件。启停的记忆和 Skills 对后续模型请求生效。 |
| 执行任务、收据和历史操作 | 全历史或按 ID 看具体回执 | 任务归档和业务审计可编辑 | 正在运行的检查点由执行器维护。此次改动生成的事务回执独立保存，可查询及撤销。 |
| 来源、同步墓碑、旧采购和库存审计、冲突关联、本机文件状态 | 目录及文档路径 | 记录级工具或原始文档 | 文件往返仍需用户选择文件。修改本机状态不代表外部文件已同步。 |
| 备份、恢复快照、记账草稿、模型及上下文设置、本机费用估算 | 文档路径分页或字段结构 | JSON Patch | 验证备份、附件和设置结构。账本授权、设备凭据、外部账户和浏览器通用文件不在工具目录。 |

工具为 `list_data_sources`、`query_records`、`read_document`、`mutate_records`、`apply_json_patch`、`get_change_history`、`undo_change` 和 `owner_send_attachment`。原生模型根据自然语言选择工具。通用写入可以在一批中顺次处理相关记录。独立事项可分开提交。JSON Patch 支持 `test`、`add`、`replace`、`remove`、`copy` 和 `move`。旧格式没有 ID 的列表项用查询给出的行定位，跨会话重排后应重新读取。

## 拒绝条件审计

| 原限制或条件 | 位置 | 分类与调整 |
|---|---|---|
| 原生工具只有特定新增和撤销。通用文档权限只作用于旧流程 | `ai/agent-tools.mjs`、`ai/documents.mjs`、`ai/chat.mjs` | 删除限制：接入统一的授权和交易工具。 |
| 对话、记忆、档案和部分用量不在普通查询范围 | `ai/data.mjs`、`ai/agent-tools.mjs` | 删除限制：所有者工具对本机业务集合分页查询。 |
| 指定时间、查询关键词或最近 40 条才能找到旧证据 | `ai/workspace.mjs`、`ai/conversation-evidence.mjs` | 删除所有者查询限制：跨历史查消息、附件目录和回执。 |
| 健康写入要求逐字原话、相同数值和明确措辞 | `ai/health-actions.mjs`、`ai/evidence.mjs` | 删除所有者的逐字门槛。单包装、单位和账本结构仍由程序核验。 |
| 只有当前轮能提供计划和稳定偏好的证据 | `ai/agent-tools.mjs`、`ai/memory.mjs` | 删除所有者的复制原话要求。新偏好由模型理解，旧值在日志里。 |
| 净金额需以固定措辞出现在这轮文字里。旧交易只能走特定候选 | `ai/agent-executor.mjs`、`ai/finance.mjs` | 删除所有者的语句限制：可直接改交易、填净额或按分计算差额。 |
| 无付款、退款凭据就无法记账 | `ai/receipts.mjs` | 截图识别工具保留证据完整性校验。所有者可以按声明编辑账目或登记独立退款。 |
| 同额采购和同日入库可能被判断为重复 | `ai/receipts.mjs`、`ai/stock-receive.mjs` | 改为操作 ID、可定位源证据及短时间相同新增指令去重，明确独立采购可另外登记。 |
| SKU 原单位固定，改单位可能生成同名 SKU | `health/inventory.mjs` | 用原 SKU 的实盘事务替代拒绝。保留历史单位、成本、原始记录和关联证据。 |
| 旧支出、旧饮食或旧采购只能整批撤销。关联库存的记录限制改量 | `ai/data.mjs`、`ai/deletion.mjs`、`health/purchases.mjs` | 用逐项修订、有效库存重算、保留历史或定点归档替代。 |
| 标签缺照片、入库数量文字有别、没 SKU 无法按旧流程提交 | `ai/stock-receive.mjs`、`ai/health-actions.mjs` | 删除所有者的照片门槛。保存声明的数值并保留来源。缺 SKU 时可记录独立实际摄入。 |
| 症状的每个字段必须逐字出现，体检报告只能来自本轮附件 | `ai/medical-chat.mjs`、`ai/agent-tools.mjs` | 所有者可用既往资料或用户声明补录、更正。保持症状和诊断类型约束。 |
| 专用健康工具最多 8 步，部分工具限制餐数、分页和参数个数 | `health/contract.mjs`、`ai/agent-tools.mjs` | 所有者批量工具不继承专用工具的条目上限。读取分页，长任务有检查点。 |
| 回合数、重复参数和无进展上限 | `ai/agent-loop.mjs` | 保留防死循环保护。所有者单次续跑窗口为 96 个模型回合，已提交步骤可凭原 ID 重试。 |
| 多个可能的包装、没有可靠单位换算、采购晚于关联消耗 | `health/containers.mjs`、`health/purchases.mjs` | 保留物理和时间关系校验。可先保存可靠事实或重新盘点，无法自动推断的关系由用户指定。 |
| 普通自动写入开关、限额和逐项确认 | `ai/finance.mjs`、`ai/agent-tools.mjs` | 所有者使用自己的权限分支。下单、记账、历史更正无需重复打开普通开关或逐项确认。 |
| 任意键、外部指令、损坏附件、非法金额、库存负值和重复关联 | `ai/owner.mjs`、`ai/document-patch.mjs`、`health/sync.mjs` | 保留授权范围、格式、完整性和关系校验。附件和账本内容只作为证据。 |
| 跨存储没有原生原子提交 | `health/storage.mjs`、`health/purchase-sync.mjs` | 用待同步事务、版本检查、逐库校验和补偿回滚。 |

## 写入和回滚

本机先基于账本版本试算，校验格式和依赖，随后暂存事务、写入涉及的业务文档，最后在同一次 IndexedDB 提交内写健康数据和回执。恢复点只记录这次操作涉及的健康字段和实际修改的其他文档。财务使用原来的主键、恢复副本和预算计算。另一页面修改了同一数据时会报出具体冲突。未完成事务可从原任务继续，也可在待同步入口回滚。撤销保留后续无关操作，若同一字段之后被改过则提示重新核对。

## 验收边界

- 浏览器使用合成账本，验证 390px 深色聊天、可折叠执行详情、撤销、真实 IndexedDB 中断、页面重载和财务补偿。
- 真机 iOS 仍需要验收。合成 API 用例覆盖净额、SKU 重盘点、历史跨域修改和档案追问，业务规则与权限另有单元和浏览器测试。
- 极端混合旧格式、历史上缺少稳定身份或原件实际已丢失时，模型应说明具体的缺口。直接使用 JSON Patch 修改关联流水时，需要在同一事务给出匹配的关系字段。
- 恢复点和变更日志存在本机。现有备份及同步会保留业务数据和原有归档选项，所有者逐次事务日志暂无文件迁移入口。

## 0.9.23 关联修订和恢复

JSON Patch 先按原始路径解析整批修改，再按稳定 ID 修订饮食和采购。已有食用改份量时一起重算扣库、营养与成本。SKU 改变时先释放原扣库，只有单位换算有依据才扣新库存。缺少换算依据时保留实际记录，相关扣库和数值标为待核算。删除健康采购会收回在库量、移除未使用批次及包装，并将已有消耗的批次归档。原财务支付继续作为独立交易保存。删除财务交易需要明确修改对应财务记录。

保存前比较本次提交引入的关联异常，包括丢失的批次入库、饮食扣库量或 SKU 不符、包装对应流水不符，以及采购与财务或收据断链。已有旧账异常可以保持原样。直接修改流水仍可使用 Patch，在同一提交里保持相关记录一致。包装已有后来称重时，修订旧饮食可保留物理称重差作为待核对记录。

日常换机请用健康与财务的统一备份恢复目标时点。备份包含账本状态，可以恢复到导出时点。逐次撤销记录目前只存在原设备的 IndexedDB，换机后可撤销的是新设备上的新操作。保留换机前的统一备份可以在需要时恢复该时点。合并前的本机快照与逐次撤销记录是独立的恢复入口。

财务完整快照仅在跨库事务待提交时暂存，成功或回滚后清除。新的本机历史保存变动字段和记录，旧版历史照常可读。明确替换整份财务账本、删除全部交易或调整整列顺序时，实际修改范围可能仍需要较大恢复点。用 10,001 条合成交易改一笔金额时，财务历史部分从约 7.4 MB 降至 445 字节（JSON 序列化大小，IndexedDB 存储开销另计）。
