# 独立包装库存

展开库存中的食品，点对应的瓶、盒或分装份。首次使用保存含包装的初始毛重，此后录入同一个包装的最新毛重。确认前可查看重量差、营养和成本；日期和餐次可以修改。只有一个已开包装时，商品下方的「记录最新毛重」会直接选它。多个已开包装分别从各自的条目进入。

「更多操作」可记录洒出、补充、重新称重或空包装重。重新称重只更新基准并保留原因。关闭前可选择「已用完」或「丢弃剩余」。净余需要空包装重或实称净重作为依据。标称容量独立展示，对估算的分装重量标注「约」。以体积标示营养的食品，需要已确认体积或可靠密度。

在「手动管理」里可以记录各份分装重量，也可以把生料批次转成熟制分装。制作时录入实际投料、各袋熟重，原料出库，成本下分到各袋。同一熟食 SKU 的每次制作都有独立批次。蔬菜分装可用「计划当天午晚餐」，计划不影响库存。

## 存储和同步

- `local.containers` 保存包装 ID、SKU、来源批次、标称规格、实称或估计初始净重和成本来源。继承期初的包装使用稳定的期初批次标识，已有采购与分装继续引用原批次。
- `local.containerEvents` 按包装串联初始毛重、续称、净重消耗、损耗、补充、纠正和关闭。操作 ID 用于重试，前序 ID 用于检查称重基准。状态、最新毛重与累计量从事件推导。已用完的包装还能在「批次与流水」查看。
- 旧账迁移新增关系。已有完整盒装摄入、分装批次与有明确证据的称重记录沿用原饮食和库存流水。包装标称容量不作为食用上限。
- 同步包和外部增量回写都携带包装日志。同一包装的分叉在预览中待核对，保留本机分支后其他包装可以继续合并。原始表的外部修改仍由版本化 JSON 回写流程核对。
- 后续接口可调用 `previewPackageAction(state, input)` 与 `confirmPackageAction(state, input)`。传包装 ID；仅指定 SKU 时，只有一个开封包装或一个可用包装才会自动匹配。提交时传稳定操作 ID 和预览得到的 `container.head` 作为 `expectedHead`。
