# 健康账本文件往返

## 手机上合并

在健康页打开 **设置 → 合并导入与文件同步 → 选择文件并预览**。文件可以是 `health_tracker_YYMMDD.N.json`、Airplane 健康备份、含健康数据的统一备份或同步包。若文件没有可靠来源 ID，给同一主账填同一个固定来源名称。各个独立主账使用不同名称。

打开待核对项，对照本机记录、来源值和日期汇总。确定是同一笔就保留本机或采用更正，确定是另一笔才选独立加入。文件中的财务交易只用于提醒，合并过程对财务账是只读的。选择 **保存快照并合并** 时，应用在同一 IndexedDB 事务中保留合并前的健康与财务完整快照，再写入合并结果。中断时可重新打开应用核对结果。需要回退时，先导出今天更新后的账本，再导出合并前快照，从 **完整备份与恢复** 选择要恢复的账本。

## 将手机新增或更正带回外部主账

在同一菜单 **导出健康同步包**，把 JSON 复制到维护外部主账的电脑。包中含健康数据、设备来源、版本、上次匹配锚点、事件变更和显式删除记录。同步包也能在 Airplane 通过合并导入打开。

先用 Node.js 22 在仓库根目录运行只读预览：

```sh
node tools/merge-health.mjs --base health_tracker_301120.1.json --incoming airplane-health-sync-demo.json
```

预览返回待核对项的 `id` 与可选 `value`。把选择写成 JSON 对象。遇到 `stage: external` 时用 `external` 对象填写这一步的选择，遇到 `stage: incoming` 时用 `incoming`。无冲突可以省略 `--choices`。手机上填写过自定义固定来源名称时，用 `--source` 传同一个名称。

```json
{"incoming":{"foods:示例ID":"keep","baselines:示例ID":"take"}}
```

再次运行，指定一个新版本文件名：

```sh
node tools/merge-health.mjs --base health_tracker_301120.1.json \
  --incoming airplane-health-sync-demo.json --choices reviewed.json \
  --out health_tracker_301121.1.json --version 301121.1
```

核对输出 JSON 后，再人工替换外部工作流所用版本，更新 ChatGPT Library 或重建 SQLite 查询镜像。工具不会覆盖已存在的输出文件，也不会连接 ChatGPT Library 或 SQLite。

## 合并口径

- 记录按来源、稳定 ID、精确内容、同日同类候选对齐。旧行的数组位置仅用于追溯同一快照的原始字段。两边都改过、存在多条相似摄入、来源与手机已有扣库发生冲突时，先由使用者核对。
- 分开比较实际饮食和计划。每日汇总只继承未被对应事件覆盖的基线差额。原有汇总无法解释时，预览提示按事件重算或核对原值。体重、能量、成本和周期由现有规则计算。
- 外部库存是净盘点余额，外部采购历史与库存审计以可查资料保留。接受来源余额时保留本机流水，避免再扣一遍。Airplane 的批次、扣库、采购和模板按关联关系合并。涉及已关联财务支出的金额、日期或撤销更正时，在库存页改原订单。
- 合并菜单可查看外部别名、单价、采购、库存审计与现行规则。库存搜索可用别名，同单位单价可补充缺失的库存成本。AI 可通过 `sync_catalog` 按关键词、日期或 ID 查询。
- 双向同步以人工传文件为准。没有稳定行 ID、持有多个不相干的主账、或外部只改了未知字段时，应保存原文件并仔细核对预览。SQLite 镜像的字段兼容由原工作流的镜像工具负责。
